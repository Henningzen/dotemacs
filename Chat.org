#+TITLE: On =gptel-cache= in setup-gptel.el

- Short answer

Your instinct is right, with one correction of emphasis:

- =gptel-cache= is /backend-scoped, not model-scoped/. It is honoured
  only by the Anthropic backend; every other backend ignores it.
- Within Claude, caching works across the range, but the /minimum
  cacheable prefix/ differs by model class, which is why it feels like
  an "Opus/Sonnet thing".

So: keep the setting, but move it next to the Anthropic backend and
document /why/ it is there. Left dangling mid-file it reads as debris.

- Why: what the setting actually buys you

Anthropic lets you place /cache breakpoints/ in a request. Everything
before a breakpoint is stored server-side; on the next turn that prefix
is re-read rather than re-processed.

- Cache /write/: ~1.25× base input price.
- Cache /read/: ~0.1× base input price.
- Default TTL: ~5 minutes, refreshed on each hit.

The economics only work when the prefix is /stable and large/, and when
turns arrive /close together/. That is exactly a live pair-programming
buffer — which is what your comment was reaching for.

The three symbols map to the three stable prefixes, in the order the
API requires them:

| symbol    | caches                         |
|-----------+--------------------------------|
| =tool=    | tool/function definitions      |
| =system=  | the system directive           |
| =message= | conversation turns so far      |

Anthropic allows /at most 4 breakpoints/; your list of three is safe.

- The model caveat you were sensing

Caching is refused silently if the prefix is shorter than the minimum:

- Sonnet / Opus class: ~1024 tokens.
- Haiku class: ~2048 tokens.

/Verify against current Anthropic docs — these numbers have moved./

/Key insight for your config:/ your longest directive
(=gptel-directive-writing-buddy=) is well under 1024 tokens. So
=system= caching alone will typically /no-op/. The win comes from
=message= once the buffer has accumulated a few thousand tokens — which
is precisely the "persistent buffer" case.

Practical consequence: caching is near-useless for your
=claude-haiku= profile and for one-shot =gptel-send= queries, and
genuinely valuable for long =architect= / =common-lisp= sessions on
Opus.

- Recommended: keep it global, but sited and commented
