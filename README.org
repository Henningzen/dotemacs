** corfu / cape

   In-buffer completion UI, the companion to Vertico for
   =completion-at-point=. Corfu take care of rendering the popup, while
   Cape supplies extra backends (file paths, dabbrev, etc.).

   Configured in 'settings/setup-corfu.el'.

*** Why Corfu, not Company:
    - CAPF-native (completion-at-point-functions) same minimalist
      philosophy as Vertico and Orderless.
    - Works automatically with Cider and Sly - no config per backend
    - Less complexity from fewer moving parts, and lighter than
      company-mode

*** Behaviour:
    - Popups will appear automatically while typing (corfu-auto)
    - corfu-popupinfo shows docs for the selected candidate

| Key     | Description                                  |
|---------+----------------------------------------------|
| =TAB=   | Complete / cycle candidates                  |
| =C-n=   | Next candidate                               |
| =C-p=   | Previous candidate                           |
| =RET=   | Accept selected candidate                    |
| =C-g=   | Abort completion                             |
| =M-d=   | Toggle documentation popup (corfu-popupinfo) |
| =C-M-i= | Manually trigger completion-at-point         |

** sly

   Common Lisp IDE. Configured in 'settings/setup-sly.el'.

*** Setup notes:
    - SBCL installed system-wide via =apt install sbcl= (=/usr/bin/sbcl=)
    - =inferior-lisp-program= set to "sbcl"
    - Completion via completion-at-point - works with Corfu, no extra wiring
    - Contribs: sly-quicklisp, sly-asdf (loaded if present)

*** Quicklisp:
    - Installed per-user in =~/quicklisp/= (NOT system-wide / not under sudo)
    - Loaded at SBCL startup via =~/.sbclrc= (written by =ql:add-to-init-file=)
    - Because Sly launches sbcl as your user, it reads your ~/.sbclrc and
      Quicklisp is available automatically in the REPL

*** NOTE to self:
    - Files in $HOME must be owned by your dev user, not root. A missing or
      root-owned ~/.sbclrc is the usual cause of the slynk-quicklisp
      MISSING-DEPENDENCY error at connect time.

* Using Emacs

** Completion

   We got two complementary strategies for text completion:

*** Primary: Corfu (automatic popup)

    Default completion UI that pops up while you type. Works with Cider,
    Sly, and file paths via Cape. This is the best choice for typical
    completion scenarios.

| Key     | Description                                  |
|---------+----------------------------------------------|
| =TAB=   | Complete / cycle candidates                  |
| =C-n=   | Next candidate                               |
| =C-p=   | Previous candidate                           |
| =RET=   | Accept selected candidate                    |
| =C-g=   | Abort completion                             |
| =M-d=   | Toggle documentation popup (corfu-popupinfo) |
| =C-M-i= | Manually trigger completion-at-point         |


*** Supplementary: Hippie-expand (manual expansion)

    Triggered manually with ~M-/~. Cycles through various expansion
    strategies (dabbrev, file names, lines, symbols). Gives me an option
    for different expansion styles or if I need more control.

| ~M-/~     | Smart expansion with all strategies                       |
| ~C-M-/~   | Expand full lines only (great for repeating similar code) |
| ~C-c /~   | Case-sensitive expansion                                  |
| ~C-c M-/~ | Words/symbols only (no file paths or lines)               |
| ~C-c C-/~ | Current buffer only (faster, less noise)                  |
| ~C-c f /~ | File name completion only                                 |

* Python

  Python on the uv toolchain.
  Configured in 'settings/setup-python.el'.
  - uv            → ONE binary replaces pyenv/pip/virtualenv/poetry
  - basedpyright  → types, navigation, rename - the PyCharm-parity piece
  - ruff          → lint - format - import sort (add-on LSP server)
  - envrc/direnv  → per-project .venv, invisible after one-time setup
  - apheleia      → ruff format - import sort on every save
  - dape          → debugging via debugpy (modern dap-mode replacement)
  - python-pytest → magit-style transient test runner
  - org-babel     → literate exploration; optional Jupyter kernels

  Workflow:
  - basedpyright provides semantics (completion via Corfu, M-., rename),
  - ruff provides style and lint,
  - apheleia makes formatting.

** Setup notes

   + basedpyright and ruff installed per-user via =uv tool install=
     into =~/.local/bin= (added to exec-path in setup-python.el)
   + ruff runs as an add-on LSP server next to basedpyright; lint
     rules and formatting live per-project in =pyproject.toml=
   + envrc: each project needs =.envrc= with =. .venv/bin/activate=
     and a one-time =direnv allow=
   + setup-python.el is self-contained: it does not depend on
     setup-lsp.el (Clojure, currently disabled); overlapping settings
     are identical, so enabling both is harmless
